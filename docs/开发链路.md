# Recorder 开发链路全记录

从一台干净的 Windows 机器到双端打包产物的完整链路：环境搭建 → 开发 → 模拟器调试与自动化验证 → 打包发布。所有命令、路径、报错均为本项目实录。

配套工具脚本（仓库内 `scripts/`）：

| 脚本 | 用途 |
|---|---|
| `scripts/cdp-eval.mjs` | 通过 CDP 在 app 页面里执行 JS（UI 自动化验证主力） |
| `scripts/screenshot.ps1` | Windows 桌面截图 |
| `scripts/sendkeys.ps1` | 向聚焦窗口发按键（原生文件对话框输路径） |

## 一、环境搭建

### 1.1 工具链

| 依赖 | 实测版本 | 要求 | 说明 |
|---|---|---|---|
| Node.js | v24.13.0 | ≥ 20 | |
| Rust | 1.97.0 | ≥ 1.90 | 需追加 4 个 Android target（见下） |
| JDK | 17.0.12 | 必须 17 | **Gradle 不支持更高版本**，机器上即使有 JDK 25 也要让 `JAVA_HOME` 指 17 |
| Android SDK | Platform 36 + Build-Tools 36.1.0 + NDK 29.0.14206865 + Platform-Tools | — | 只装 cmdline-tools 即可，**不需要 Android Studio IDE** |
| 雷电模拟器 | Android 14 / x86_64 | — | 在雷电设置里开启 ADB 连接 |

Rust Android targets：

```bash
rustup target add aarch64-linux-android armv7-linux-androideabi i686-linux-android x86_64-linux-android
```

用户级环境变量：

```
ANDROID_HOME = C:\Users\<你>\AppData\Local\Android\Sdk
JAVA_HOME    = <JDK 17 路径>
```

**Windows 开发者模式必须打开**（设置 → 系统 → 开发者选项）：tauri 构建 Android 要创建软链接，否则报 `Creation symbolic link is not allowed`（非管理员账号只有开开发者模式才能建软链）。

### 1.2 网络环境（本机有 TLS 拦截，必须换源）

| 源 | 替换为 | 位置 |
|---|---|---|
| npm 官方源 | `https://registry.npmmirror.com` | `npm i --registry=...`，或写进 `.npmrc`；官方源会**卡死无报错** |
| Maven 中央仓库 | 阿里云镜像 | `src-tauri/gen/android/build.gradle.kts` 与 `buildSrc/build.gradle.kts`：`maven { url = uri("https://maven.aliyun.com/repository/google") }`、`.../public` |
| shadcn registry（ui.shadcn.com） | **不用 CLI**，组件源码手入驻 `src/components/ui/` | 见 §2.5 |

### 1.3 Tauri Android 工程的本机补丁

`src-tauri/gen/` 由 `tauri android init` 生成。**重新 init 会覆盖以下全部补丁，必须重打**（§4.5 有完整清单）。

**① BuildTask.kt：Windows 上 npm 走 cmd.exe。** Gradle `exec` 不经 shell，Windows 上直接执行 `npm`/`npm.cmd` 会失败。补丁在 `src-tauri/gen/android/buildSrc/src/main/java/com/recorder/app/kotlin/BuildTask.kt`：

```kotlin
if (Os.isFamily(Os.FAMILY_WINDOWS)) {
    // Gradle exec 不经 shell，Windows 上无法直接执行 npm/npm.cmd，
    // 统一交给 cmd.exe 解释执行（本机补丁，重新 android init 后需重打）
    executable("cmd.exe")
    args(listOf("/c", executable) + args)
} else {
    executable(executable)
    args(args)
}
```

**② 关闭 Kotlin 增量编译（跨盘符报错）。** 项目在 H: 盘、cargo registry 在 C: 盘，Kotlin 增量编译报 `this and base files have different roots`。`src-tauri/gen/android/gradle.properties`：

```properties
kotlin.incremental=false
```

**③ Maven 阿里云镜像**：见 §1.2 表，两个 `build.gradle.kts` 的 `buildscript`/`repositories` 块都改。

### 1.4 雷电模拟器连接

```bash
# 雷电设置里开启 ADB 连接后：
adb connect 127.0.0.1:5555

# 常见：同时出现 emulator-5554 和 127.0.0.1:5555 两个条目（同一台设备），去重：
adb disconnect 127.0.0.1:5555
```

注意：

- **用 Android SDK 的 adb，不要用雷电安装目录自带的 adb**——版本不一致会互相踢下线（表现为设备反复 offline）。
- 雷电镜像**没有 `monkey` 命令**，启动应用一律 `am start`。
- `tauri android dev` 在"构建完成 → 安装"阶段会挂起（tauri 内置 adb 客户端与雷电兼容性问题）。绕过：让它构建完，然后手动安装启动：

```bash
adb install -r src-tauri/gen/android/app/build/outputs/apk/universal/debug/app-universal-debug.apk
adb shell am start -n com.recorder.app.debug/com.recorder.app.MainActivity
# debug 包名带 .debug 后缀；release 包名是 com.recorder.app
```

### 1.5 验证环境就绪

```bash
npm install --registry=https://registry.npmmirror.com
npm run tauri dev         # Windows 窗口能起来 = 桌面端链路通
npm run tauri android dev # 能编出 APK（安装挂起用手动法）= Android 链路通
```

排错对照表：

| 报错 | 原因 | 解法 |
|---|---|---|
| `sql.execute not allowed` | capabilities 缺 `sql:allow-execute` | §2.4 |
| `this and base files have different roots` | Kotlin 增量编译跨盘符 | §1.3② |
| `Creation symbolic link is not allowed` | 没开开发者模式 | §1.1 |
| 构建到安装阶段无限挂起 | tauri adb 客户端与雷电不兼容 | §1.4 |

## 二、开发

### 2.1 常用命令

```bash
npm run dev                 # 仅前端 vite（浏览器预览；initDb 会失败，实际不用这个调试）
npm run tauri dev           # Windows 开发模式（自动起 vite:1420 + app.exe）
```

- 端口 `1420` strictPort，HMR 走 `1421`；`TAURI_DEV_HOST` 非空时监听局域网（Android dev 需要 WebView 能访问到 PC）
- 构建 target：Windows `chrome105`（WebView2 是 Chromium），其他 `safari13`（按移动端 WebView 能力降级）

### 2.3 数据层约定（改库前必读）

- **tauri-plugin-sql 没有 JS 侧事务 API**：多步写入顺序 await；级联删除在应用层手动按子表→父表做，不依赖 PRAGMA foreign_keys
- 日期字符串一律本地时区 `YYYY-MM-DD`（`format.ts`，不要用 `toISOString` 直接截断，会差一天）
- SQLite 是 **WAL 模式**：写入先落 `recorder.db-wal`，主文件不立即变大是正常现象
- 存储位置：Windows `%APPDATA%\com.recorder.app\recorder.db`；Android 应用私有目录（无需存储权限）

### 2.4 Tauri 权限（`src-tauri/capabilities/default.json`）

```json
"permissions": [
  "core:default", "sql:default", "sql:allow-execute",
  "dialog:default", "fs:default",
  "fs:allow-write-text-file", "fs:allow-read-text-file"
]
```

- `sql:default` **只有读权限**；任何写（CREATE/INSERT/UPDATE/DELETE）必须显式 `sql:allow-execute`，否则 `sql.execute not allowed`
- dialog 的 `save()`/`open()` 选中的路径**自动获得读写授权**，无需再配 fs scope
- Android 上 `save()` 走系统 SAF，`open()` 走系统文件选择器，与 Windows 同一份代码

### 2.5 前端技术栈细节

- **tailwind v4**：经 `@tailwindcss/vite` 插件接入（`vite.config.ts` 加插件、`index.css` 用 `@import "tailwindcss"` + `@theme inline` 映射），没有 tailwind.config.js。**兼容基线 Chromium 101**（用户 vivo S9 系统 WebView，厂商锁死无法升级）：不用 oklch() / color-mix() / 独立 translate 属性；新用调色板颜色要在 `index.css @theme` 补 hex 覆盖（实录见 §2.6 坑表）
- **shadcn/ui 手入驻**：官方 CLI 要从 ui.shadcn.com 拉 registry，本机网络不可控，改为手工把组件源码放进 `src/components/ui/`（CSS 变量主题 + Radix + cva + cn()），只入驻用到的。日期/时间输入用原生 `<input type="date">/type="time">`——Android WebView 有原生选择器，移动端体验好且零依赖

### 2.6 开发期常见坑

| 现象 | 原因 | 解法 |
|---|---|---|
| app 启动白屏，console 报 `Cannot read properties of null (reading 'useRef')` | vite 在 app 启动瞬间 re-optimize 新依赖，造成 React 双实例 | 等 vite 稳定后 force-stop 重启 app |
| WebView 显示旧页面/旧逻辑 | HMR websocket 已断，bundle 没更新 | force-stop + am start 强制全量刷新（**验证修复前务必重启 app**，否则会误以为 bug 还在） |
| 子 tab 栏跟着内容滚走 | `<main>` 是唯一滚动容器 | 子 tab 栏加 `sticky top-0 z-10 bg-background` |
| 老手机界面全无颜色、对话框偏到右下（vivo S9 实测，系统 WebView Chromium 101 且无法升级） | Tailwind v4 产物：oklch()/color-mix() 需 Chrome 111+，独立 translate 属性需 Chrome 104+，老内核全部失效 | 主题色与用到的调色板色全部改 hex（`index.css` 注释留原 oklch 值）；对话框居中改 `transform`；遮罩透明度改 rgba 直写；**注释里勿写工具类原名**（Tailwind 扫描器连注释也提取，会重新生成死样式） |
| `npm run tauri dev` 报 Port 1420 is already in use | 上次 dev 的 vite 没被杀干净（孤儿进程） | 杀掉占用 1420 的 node 进程再起 |

### 2.7 提交前自检

```bash
npm run build   # tsc 类型检查 + vite 构建，必须全绿
```

## 三、模拟器调试与自动化验证

LDPlayer 上"盲点坐标"不可靠（§3.3），本项目验证的主力方案是 **CDP 直接驱动 WebView 页面**（§3.4），截图只做最终目视确认。

### 3.1 adb 手动驱动基础

```bash
ADB="/c/Users/yangs/AppData/Local/Android/Sdk/platform-tools/adb.exe"

"$ADB" shell input tap 540 1200            # 点按 (x,y)
"$ADB" shell input swipe 540 1500 540 500 300  # 上滑（300ms）
"$ADB" shell input text "150"              # 输入文本（仅 ASCII！）
"$ADB" shell input keyevent 4              # 返回键（关键盘/关对话框）
"$ADB" shell input keyevent 123            # 光标移到行尾（MOVE_END）
"$ADB" shell input keyevent 67 67 67       # 删除键×3（清空输入框：先123再连按67）
```

- **`input text` 只支持 ASCII**：输中文直接 `NullPointerException`（InputShellCommand 无法映射键码）。中文内容改走 CDP 赋值（§3.4）或数据库手术（§3.6）。
- 一串操作写在**一条** `adb shell "cmd1; sleep 0.5; cmd2"` 里链式执行——分多条 adb 命令间隔太久，模拟器上的页面状态可能已变（弹窗被抢、列表滚动）。

### 3.2 截图验证（必须 exec-out）

```bash
"$ADB" exec-out screencap -p > shot.png   # 二进制安全
```

**不要用 `"$ADB" shell screencap -p > shot.png`**：`adb shell` 的 stdout 会做 LF→CRLF 转换，PNG 二进制直接损坏。`exec-out` 是原始字节流。截图后用 Read 工具看图确认 UI 状态。

### 3.3 LDPlayer 的怪癖（实录）

- **触摸事件会被缓冲、随后整批重放到之后的页面**。案例：在账单页录入期间的若干 tap 没有生效，几分钟后全部被"回放"到班时日历上，瞬间误标 14 个工作日（数据库里 created_at 间隔整齐 ~300ms 就是重放的指纹）。**结论：关键验证不要依赖 tap，用 CDP**。
- 顶栏存在**坐标死区**：同一排按钮 `y=138` 间歇性失灵、`y=155` 有效（`dumpsys input` 显示窗口布局正常无覆盖层，原因未明）。tap 没反应时先换 y 坐标试。
- 其他 app（聊天应用、企业应用 io.dcloud.HBuilder 等）会**抢前台**导致 tap 落空；重要操作链前先看一眼当前前台 app：`adb shell dumpsys activity activities | grep topResumedActivity`。
- SAF 保存框（导出备份时）可以自动化：文件名已预填，直接 tap 右下角「保存」按钮即可，文件落在 `Download`；新文件在 DocumentsUI 列表里可能显示 0B（元数据缓存假象），实际内容正常。

### 3.4 CDP 驱动 WebView（核心技巧）

Tauri debug 包的 WebView 暴露 devtools socket，可以像 `chrome://inspect` 一样用 CDP（Chrome DevTools Protocol）驱动页面——确定性执行 JS，不受模拟器触摸怪癖影响。

**① 找到 socket 并转发：**

```bash
"$ADB" shell "am force-stop com.recorder.app.debug"
"$ADB" shell "am start -n com.recorder.app.debug/com.recorder.app.MainActivity"; sleep 5
"$ADB" shell "cat /proc/net/unix" | grep -o "webview_devtools_remote_[0-9]*"
# 可能列出多个（模拟器里任何用 WebView 的 app 都有，比如 io.dcloud.HBuilder）。
"$ADB" forward tcp:9224 localabstract:webview_devtools_remote_<pid>
curl -s http://127.0.0.1:9224/json/list
# 在返回的 targets 里找 url 含 tauri.localhost 的 page——那才是我们的 app；
# 不是的话换一个 socket 再试。注意 pid 随 app 重启变化，重启后要重新发现+转发。
```

**② 执行 JS：** 用仓库脚本 `scripts/cdp-eval.mjs`（封装了 /json/list 查找 target、WebSocket、Runtime.evaluate awaitPromise+returnByValue）：

```bash
node scripts/cdp-eval.mjs my-check.js 9224
```

**③ 页面内驱动的三个招式（写 my-check.js 时用）：**

```js
// a) 按文本找按钮并点击
const byText = (sel, t, root = document) =>
  [...root.querySelectorAll(sel)].find((e) => e.textContent.trim().includes(t));
byText("button", "保存").click();

// b) React 受控输入框赋值（直接 el.value = x 无效，React 感知不到）：
const setVal = (el, v) => {
  Object.getOwnPropertyDescriptor(HTMLInputElement.prototype, "value").set.call(el, v);
  el.dispatchEvent(new Event("input", { bubbles: true }));
};
setVal(document.querySelector("input"), "母亲生日"); // 中文也没问题！

// c) 每步之间留 await sleep，等 store refresh + 重渲染
const sleep = (ms) => new Promise((r) => setTimeout(r, ms));
```

**④ Windows 端同理（WebView2）：**

```bash
WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS="--remote-debugging-port=9229" npm run tauri dev
node scripts/cdp-eval.mjs my-check.js 9229   # 认 url 含 localhost:1420 的 page target
```

**⑤ Windows 桌面截图**（看窗口真实状态）：`scripts/screenshot.ps1`，输出项目根 `shot-win.png`。

### 3.5 原生文件对话框（Windows 导入/导出验证）

CDP 管不到 WebView 之外的原生对话框。用 `scripts/sendkeys.ps1` 向聚焦的对话框发按键：

```bash
# 先 CDP 点击「导入备份」触发 open 对话框，然后：
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/sendkeys.ps1 -Path 'H:\...\backup-android.json'
# 对话框文件名框输入路径 + 回车 → 回到页面出现确认框，继续 CDP 点「全量替换导入」
```

局限：按键发给**当前焦点窗口**——有人操作电脑、焦点被抢就会打飞（实战中两次被打断，最后改为请用户手动点）。**结论：Windows 端涉及原生对话框的验证，让人来操作最稳。**

另一个坑：bash 里 `powershell -Command "$ws = ..."` 的 `$ws` 会被 bash 先展开成空串——PowerShell 代码一律写 `.ps1` 文件用 `-File` 执行。

### 3.6 应用数据库直接手术（应急/测试数据清理）

debug 包 `run-as` 可读写应用私有目录，可以直接换整个 SQLite 库。案例：清理模拟器里被误标的 14 个工作日。

```bash
# 1) 停 app（必须，否则 WAL 状态不一致）
"$ADB" shell "am force-stop com.recorder.app.debug"

# 2) 拉库（exec-out 二进制安全；WAL 必须一起拉，数据大多在 WAL 里）
"$ADB" exec-out "run-as com.recorder.app.debug cat recorder.db"     > rec.db
"$ADB" exec-out "run-as com.recorder.app.debug cat recorder.db-wal" > rec.db-wal

# 3) 本地用 Node 24 内置 node:sqlite 改（先拷成 snap 副本，改完 checkpoint）
node -e "
const fs=require('fs');const {DatabaseSync}=require('node:sqlite');
fs.copyFileSync('rec.db','snap.db');fs.copyFileSync('rec.db-wal','snap.db-wal');
const db=new DatabaseSync('snap.db');
db.exec('DELETE FROM work_days');
db.exec('PRAGMA wal_checkpoint(TRUNCATE)');   // 关键：把 WAL 合并回主文件
db.close();"

# 4) 经 /sdcard 中转推回（run-as 是应用 uid，读不了 /sdcard/Download，
#    所以用 shell 读、设备内管道写给 run-as；Git Bash 里 /sdcard 要写成 //sdcard 防 MSYS 路径转换）
"$ADB" push snap.db //sdcard/Download/snap.db
"$ADB" shell "run-as com.recorder.app.debug sh -c 'rm -f recorder.db-wal recorder.db-shm'"
"$ADB" shell "sh -c 'cat /sdcard/Download/snap.db' | run-as com.recorder.app.debug sh -c 'cat > recorder.db && chmod 600 recorder.db'"

# 5) md5 校验一致 → 重启 app
"$ADB" shell "run-as com.recorder.app.debug md5sum recorder.db"; md5sum snap.db
```

注意：**不要**用 `adb shell "run-as ... sh -c 'cat > recorder.db'" < snap.db` 从 PC  stdin 直接写——adb shell 的 stdin 不是二进制安全的（实测 77KB 文件只到了 24KB 且 md5 不符）。

### 3.7 MSYS/Git Bash 路径坑汇总

- `adb push x /sdcard/...`：`/sdcard` 会被 MSYS 转成本地路径（如 `E:/software/Git/Git/sdcard`）→ 写 `//sdcard/...`
- 设备路径放进 shell 变量再展开时同样会被转换 → 同上，或设 `MSYS2_ARG_CONV_EXCL`
- PowerShell 命令行里的 `$变量` 会被 bash 展开 → 用 `.ps1` 文件

## 四、打包发布

### 4.1 前端构建

```bash
npm run build   # tsc -b（类型检查）+ vite build → dist/
```

bundle 约 667 KB（d3 + lunar-javascript 占大头），离线应用无所谓，警告可忽略。

### 4.2 Android 签名 APK

**① 生成 keystore（一次性，已 gitignore 不进仓库）：**

```bash
keytool -genkeypair -v -keystore src-tauri/gen/android/app/recorder-release.keystore \
  -alias recorder -keyalg RSA -keysize 2048 -validity 10950 \
  -storepass recorder-local -keypass recorder-local \
  -dname "CN=Recorder, OU=Personal, O=Personal, L=Local, ST=Local, C=CN"
```

**② `app/build.gradle.kts` 配签名**（本机补丁，重新 `tauri android init` 要重打）：

```kotlin
android {
    signingConfigs {
        create("release") {
            storeFile = file("recorder-release.keystore")
            storePassword = System.getenv("RECORDER_STORE_PASSWORD") ?: "recorder-local"
            keyAlias = "recorder"
            keyPassword = System.getenv("RECORDER_KEY_PASSWORD") ?: "recorder-local"
        }
    }
    buildTypes {
        getByName("release") {
            signingConfig = signingConfigs.getByName("release")
            // ...
        }
    }
}
```

**③ 构建：**

```bash
npm run tauri android build -- --apk
# 首次 release 要编译 4 个架构的 Rust（~7 分钟），之后增量很快
# 产物：src-tauri/gen/android/app/build/outputs/apk/universal/release/app-universal-release.apk（58MB，universal 全架构）
```

**④ 验证：** 安装启动，全新种子数据即成功。

```bash
adb install -r .../app-universal-release.apk
adb shell am start -n com.recorder.app/com.recorder.app.MainActivity   # release 无 .debug 后缀
```

release 与 debug 包名不同（`com.recorder.app` vs `com.recorder.app.debug`），**两台应用并存互不影响**；但签名不同的同一包名不能覆盖安装。

### 4.3 Windows 安装包

```bash
npm run tauri build
```

### 4.4 版本号

- 应用版本：`src-tauri/tauri.conf.json` 的 `version`
- Android versionName/versionCode：构建时从 tauri.conf 生成到 `gen/android/app/tauri.properties`（**自动生成勿手改**），versionCode 规则如 0.1.0 → 1000

### 4.5 换机 / 重新 `tauri android init` 补丁清单

| 补丁 | 文件 | 内容 |
|---|---|---|
| npm 走 cmd.exe | `gen/android/buildSrc/.../BuildTask.kt` | §1.3① |
| Kotlin 增量编译关闭 | `gen/android/gradle.properties` | §1.3② |
| Maven 阿里云镜像 | `gen/android/build.gradle.kts`、`buildSrc/build.gradle.kts` | §1.2 |
| release 签名 | `gen/android/app/build.gradle.kts` | §4.2② |
| keystore 本体 | `gen/android/app/recorder-release.keystore` | 重新 `keytool` 生成；**签名换了就无法覆盖安装旧版**，用户需先卸载 |

## 五、里程碑二验证实录（方法论备忘）

本次三模块开发全程用上述工具链验证，关键收获：

1. **"修复后先重启 app 再验证"**：saveSettings 的绑定修复后，模拟器上因 HMR 断连仍跑旧代码，表现为"修复无效"假象；force-stop 重启后立过。
2. **Windows 原生对话框交给用户**：给用户操作30 秒完成，比继续调试自动化快得多。
